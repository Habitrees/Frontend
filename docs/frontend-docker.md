# Habitree Frontend Docker Documentation

## 1. Overview

The Habitree frontend is containerized using Docker with a multi-stage build.

The frontend uses React, TypeScript and Vite. Nginx serves the production-ready static files generated by Vite.

The Docker setup provides:

- Independent frontend containerization.
- Optimized production image.
- Separation of build and runtime environments.
- React Router SPA support.
- Docker Health Check.
- Independent frontend deployment.

## 2. Architecture

The Docker image consists of two stages.

### Build Stage

- Base image: `node:22-alpine`
- Installs dependencies using `npm ci`.
- Builds the application using `npm run build`.
- Generates production files in `dist/`.

### Runtime Stage

- Base image: `nginx:alpine`
- Copies the production files from the build stage.
- Serves the frontend on port 80.
- Uses Nginx SPA configuration.
- Includes a Docker Health Check.

Node.js and development dependencies are not included in the final runtime image.

## 3. Docker Configuration Files

| File             | Purpose                                           |
| ---------------- | ------------------------------------------------- |
| `Dockerfile`     | Defines the multi-stage image build               |
| `.dockerignore`  | Excludes unnecessary files from build context     |
| `nginx-spa.conf` | Configures Nginx, SPA routing and health endpoint |

## 4. Prerequisites

- Docker Desktop installed.
- Docker Engine running.
- Access to Docker Hub for pulling base images.

Node.js and npm are not required on the host machine for Docker-based execution.

## 5. Build the Image

Run from the frontend project root:

```bash
docker build -t habitree-frontend:local .
```

The build process:

1. Pulls or reuses the required base images.
2. Installs dependencies using `npm ci`.
3. Copies frontend source files.
4. Executes `npm run build`.
5. Copies the generated `dist/` files into Nginx.
6. Creates the final frontend image.

### API Build Configuration

The Dockerfile defines:

```dockerfile
ARG VITE_API_BASE_URL=/api
ENV VITE_API_BASE_URL=${VITE_API_BASE_URL}
```

Vite embeds `VITE_` variables into the frontend bundle during build time.

To override the default API base URL:

```bash
docker build --build-arg VITE_API_BASE_URL=/api -t habitree-frontend:local .
```

These variables are public frontend configuration and must never contain secrets.

### Verify the Image

```bash
docker images habitree-frontend
```

The project image size requirement is below 500 MB.

Initial local measurement:

- Disk Usage: 94.3 MB
- Content Size: 26.6 MB

Actual values may vary between environments.

## 6. Run the Container

```bash
docker run -d --name habitree-frontend -p 8080:80 habitree-frontend:local
```

Port mapping:

| Host Port | Container Port |
| --------- | -------------- |
| 8080      | 80             |

Open the application:

`http://localhost:8080`

The host port can be changed if port 8080 is unavailable.

### Verify Container Status

```bash
docker ps --filter "name=habitree-frontend"
```

## 7. Nginx and React Router

The frontend Nginx configuration:

- Listens on port 80.
- Serves static files from `/usr/share/nginx/html`.
- Uses `index.html` as the entry point.
- Supports React Router through SPA fallback.
- Configures caching for static assets.

SPA fallback:

```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

This allows valid client-side routes to load the React application.

A successful HTTP 200 response confirms that Nginx serves the SPA entry point. Actual route rendering should also be verified in the browser.

## 8. Health Check

The frontend exposes:

`/health`

Test the endpoint:

```bash
curl -i http://localhost:8080/health
```

Expected response:

```text
HTTP/1.1 200 OK

ok
```

### Docker HEALTHCHECK

The Dockerfile includes:

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
  CMD wget -q -O /dev/null http://127.0.0.1/health || exit 1
```

Configuration:

| Parameter    | Value      |
| ------------ | ---------- |
| Interval     | 30 seconds |
| Timeout      | 3 seconds  |
| Start period | 5 seconds  |
| Retries      | 3          |

Check health:

```bash
docker inspect --format="{{.State.Health.Status}}" habitree-frontend
```

Expected status:

`healthy`

**Note:** This check verifies frontend Nginx availability only. It does not verify Backend connectivity or database health.

## 9. API Integration

The frontend Axios client uses:

```typescript
baseURL: import.meta.env.VITE_API_BASE_URL || "/api";
```

The intended API base path is:

`/api`

The standalone frontend container does not currently proxy API requests to the Backend.

During full-system integration, the shared Nginx Gateway will route `/api/` requests to Django REST API.


```bash

```

## 11. Rebuild After Changes

After modifying frontend source code or Docker configuration:

```bash
docker build -t habitree-frontend:local .
```

Remove the previous container:

```bash
docker rm -f habitree-frontend
```

Run the updated image:

```bash
docker run -d --name habitree-frontend -p 8080:80 habitree-frontend:local
```

Verify:

```bash
docker ps
```

## 12. Troubleshooting

| Problem                       | Possible Solution                          |
| ----------------------------- | ------------------------------------------ |
| Docker Engine unavailable     | Start Docker Desktop                       |
| Base image download fails     | Check network, proxy and Docker Hub access |
| Port 8080 is occupied         | Use another host port                      |
| Container fails to start      | Check Docker logs                          |
| Health status is unhealthy    | Inspect health-check logs and `/health`    |
| Changes are not visible       | Rebuild image and recreate container       |
| React route displays an error | Verify the route in React Router           |

## 13. Security and Repository Guidelines

- Do not commit local environment files or secrets.
- Keep `.env.example` as a non-secret configuration template in Git.
- Exclude `node_modules`, `dist`, `.git` and local environment files from Docker build context.
- Never expose private credentials through `VITE_` variables.
- Do not expose Backend or database ports publicly in production.
- Keep frontend Docker configuration independent from Backend Docker configuration.

## 15. Future Full-System Integration

The complete Habitree deployment will use a shared Docker Compose configuration containing:

- `frontend`
- `backend`
- `db`
- `nginx`

The shared configuration will provide:

- Common internal Docker networking.
- Service-to-service communication.
- Persistent database storage using Docker volumes.
- Centralized request routing.
- Coordinated service startup.

The complete system is intended to start using:

```bash
docker compose up -d
```

This configuration will be finalized jointly with the Backend team.
